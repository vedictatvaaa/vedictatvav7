# Grounded Puja Smart Search

## Goal

Upgrade the Online Puja Booking search bar so a devotee can type either a Puja name or a life situation such as “moving into a new home” and receive useful, catalogue-grounded suggestions. The feature must preserve links to the existing native Puja guides and booking flow.

## Scope

### In scope

- Instant autocomplete from the existing `/api/pujas` catalogue.
- Intent-aware matching for free-form queries.
- A server-side AI classification endpoint that returns only existing catalogue slugs.
- Deterministic local matching as the first response and as an AI outage fallback.
- A dropdown with exact matches and a “Based on what you described” section.
- Direct links to `/puja-guide/:slug` and the existing booking URL.
- Keyboard navigation, Escape-to-close, outside-click dismissal, and accessible live status.
- Tests for matching, response validation, fallback behavior, and the main UI states.

### Out of scope

- Generating new Puja or ritual pages.
- Generating ritual facts, prices, Pandit availability, ratings, or booking eligibility.
- Replacing the existing booking form or its server-side authority.
- Changing the Puja catalogue schema or guide content.
- Sending every keystroke to the AI provider.

## Product behavior

The existing search input becomes a smart search surface:

1. When focused or edited, it can show up to six catalogue suggestions.
2. Exact name, alias, deity, category, intent, ceremony, festival, and description matches appear first.
3. After a short debounce, free-form queries can be sent to the smart-search endpoint when local matching is weak or clearly intent-like.
4. AI suggestions appear under the label “Based on what you described”.
5. Each suggestion shows the existing Puja name and catalogue summary, plus:
   - “Understand the Puja” → `/puja-guide/:slug`
   - “Book this Puja” → the existing `/book-pandit-online?service=...&mode=...` booking URL
6. Selecting the main suggestion navigates to the existing guide. Users can continue to the existing booking action from that guide or use the direct booking link.
7. If the AI request fails, times out, or returns invalid slugs, local catalogue results remain available and the UI does not show an error state for the user.
8. Empty and no-match states keep the current clear/reset behavior.

## Grounding and safety

- The catalogue returned by `/api/pujas` is the source of truth for names, descriptions, aliases, and links.
- The AI endpoint receives a bounded catalogue projection and may return only catalogue slugs.
- The server validates every returned slug against the active catalogue before returning it.
- The client joins returned slugs back to the already-loaded catalogue records; it never renders AI-provided copy as a fact.
- Booking URLs continue to use the existing service name and mode parameters. The server remains authoritative for canonical Puja resolution, pricing, Pandit matching, availability, and eligibility.
- No ratings, reviews, people, coordinates, prices, availability claims, or SEO claims are generated by this feature.

## Architecture

### Client

Update `client/src/components/puja/PujaDiscoveryHub.tsx`:

- Keep the existing catalogue query and filter behavior.
- Add a small search state machine: closed, open with local suggestions, loading intent suggestions, and open with grounded intent suggestions.
- Normalize local searchable fields once per catalogue item.
- Add keyboard and pointer selection behavior without changing the existing catalogue result grid.
- Keep the current native guide and booking links as the only destinations.

### Server

Add a focused smart-search handler near the existing Puja content routes:

- `POST /api/pujas/smart-search`
- Request: `{ query: string, mode?: "online" | "offline" }`
- Response: `{ matches: Array<{ slug: string; confidence: "high" | "medium" }> }`
- The handler loads active catalogue records, limits the prompt projection to grounded searchable fields, calls the existing AI provider abstraction, parses structured output, validates returned slugs, and filters by the requested mode.
- Invalid or unavailable provider responses return an empty match list with a successful response so the client can use deterministic fallback.
- Apply input length limits and a short server timeout.

The endpoint must not create or update catalogue content and must not call the booking system.

## Data flow

```text
typed query
  -> local catalogue normalization and ranking
  -> immediate exact/keyword suggestions
  -> debounce
  -> smart-search endpoint for intent-like queries
  -> validated catalogue slugs
  -> client joins slugs to loaded catalogue records
  -> existing guide and booking links
```

## Interaction and accessibility

- The input keeps its existing label and placeholder, with a visible “Smart search” cue.
- The suggestion panel uses `role="listbox"` and `role="option"` with stable active-descendant behavior.
- Arrow Up/Down moves through suggestions; Enter opens the active result; Escape closes the panel.
- The current query remains in the field after selection or navigation.
- A concise `aria-live` status announces result counts and intent matching without duplicating visible copy.
- Touch targets remain at least 44px high.
- The panel is positioned within the hero and remains usable on narrow screens.

## Error handling

- Catalogue loading errors keep the existing retry UI.
- AI timeout, provider outage, malformed JSON, unknown slug, or rate limit silently falls back to local results.
- Empty AI results do not replace useful local matches.
- The booking flow is not blocked by smart-search errors.
- Analytics or logging may record technical failures, but no private query content should be persisted.

## Testing

### Unit tests

- Local ranking prioritizes exact name and alias matches.
- Intent phrases map only to catalogue records.
- Mode filtering excludes Puja records not eligible for the requested mode.
- Server output rejects unknown slugs and malformed provider responses.
- AI failure returns deterministic fallback behavior.

### Browser/component tests

- Focusing and typing opens the suggestion panel.
- Keyboard selection navigates to the native guide link.
- Direct booking action preserves the existing service and mode query parameters.
- A free-form query renders grounded intent suggestions when the server returns valid catalogue slugs.
- Empty, loading, and AI-fallback states remain accessible.

### Acceptance criteria

- “griha” immediately suggests the existing Griha Pravesh guide.
- “moving into a new home” can produce grounded suggestions from existing catalogue records.
- Every displayed suggestion has a working native guide or booking destination.
- No AI-generated unsupported ritual facts appear in the panel.
- Existing catalogue filters, cards, guide links, and booking flow continue to work unchanged.
