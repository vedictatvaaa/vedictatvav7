# Unified Brand Studio

## Goal

Extend the existing Admin Site Settings page with a unified Logo & Wordmark studio. Admins can configure the brand once and apply it consistently to the desktop header, mobile header, mobile side menu, and footer.

Existing branding remains the default. Current pages, customers, authentication, navigation, and saved logo URLs continue to work without requiring migration by the user.

## Admin Experience

The existing Site Settings branding area gains:

- Display mode: text only, image only, or image and text
- Custom logo image upload
- Logo size with bounded numeric and slider controls
- Responsive scale/enlargement control
- Position: left, center, or right
- Logo text color
- Optional tagline with show/hide control
- Tagline color and size
- Font source: curated font or uploaded custom font
- Curated logo font selection
- Custom WOFF or WOFF2 font upload
- Font weight: regular, medium, or semi-bold
- Letter spacing
- Reset to brand defaults
- Live previews for desktop header, mobile header, side menu, and footer

Controls save through the existing Site Settings save action so branding and appearance remain one coherent configuration.

## Shared Rendering

A shared brand component consumes the saved configuration and renders it in:

- Desktop top navigation
- Mobile top navigation
- Mobile side menu
- Footer

The component supports text, image, or combined display modes. Each placement respects the shared settings while enforcing local responsive limits so branding cannot overlap navigation controls or overflow narrow screens.

Position applies within each placement's available brand region. Mobile header centering remains relative to the viewport. Desktop and footer layouts adapt surrounding content to prevent collisions.

## Data and Compatibility

The existing `site_settings` record remains the source of truth. Existing `siteName`, `tagline`, and `logoUrl` values remain supported. New settings are additive and receive defaults matching the current brand:

- Display mode
- Logo size and scale
- Position
- Logo color
- Tagline visibility, color, and size
- Logo font source, family, uploaded font URL, weight, and letter spacing

Old records render correctly through schema defaults and client-side normalization.

## Uploads and Validation

Admin-only upload endpoints handle:

- Logo images: PNG, JPG/JPEG, WebP, and safely validated SVG
- Fonts: WOFF and WOFF2 only

Uploads use strict extension, MIME, size, and content checks. File names are generated by the server. Uploaded paths are stored as managed local upload URLs. Arbitrary executable formats and untrusted CSS are rejected.

Server validation constrains:

- Display mode and position to supported enums
- Sizes, scale, weight, and letter spacing to safe numeric ranges
- Colors to valid hex values
- Text lengths
- Curated fonts to an allowlist
- Uploaded asset URLs to managed paths or approved HTTPS URLs for backward compatibility

The existing Admin authentication middleware and audit logging protect all writes.

## Error Handling

- Invalid uploads return specific, user-readable errors.
- Upload failures do not discard unsaved form changes.
- Invalid values are rejected before persistence.
- Missing or failed custom assets fall back to the configured text wordmark.
- Reset restores the current Vedic Tatva defaults without immediately saving.

## Accessibility and Performance

- Preview controls have associated labels and keyboard support.
- Color controls retain editable hex values.
- Image logos require meaningful alt text derived from the site name.
- Custom fonts use `font-display: swap`.
- Uploaded fonts and images are loaded only when selected.
- Previews use the same shared brand renderer as production placements.

## Verification

- Existing records render unchanged before Admin saves new options.
- All display modes work in every brand placement.
- Position and scale remain collision-free at mobile, tablet, and desktop widths.
- Invalid image/font uploads and invalid setting values are rejected.
- Admin authorization protects upload and save endpoints.
- Reset and save behavior are covered.
- Navigation, mobile drawer, footer links, and authentication remain functional.
